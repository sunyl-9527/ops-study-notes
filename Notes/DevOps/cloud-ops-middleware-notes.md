# 云计算运维中间件学习笔记

> 适用对象：已经掌握基础运维工具，希望系统理解常见中间件部署、维护、监控和故障排查的学习者。
>
> 文档定位：这是一份中间件专题学习笔记，不再承担整体学习路线职责；整体路线统一放在 [cloud-ops-roadmap.md](./cloud-ops-roadmap.md)。

## 一、中间件在运维中的位置

中间件是业务系统和底层基础设施之间的重要支撑层。它通常不直接承载业务逻辑，但会影响业务访问、数据存储、缓存、异步处理、日志检索、配置管理和服务发现。

常见中间件可以按功能分为：

| 类型 | 常见组件 | 主要作用 |
|---|---|---|
| Web 与代理 | Nginx、HAProxy | 入口流量、反向代理、负载均衡、HTTPS |
| 数据库 | MySQL、PostgreSQL | 结构化数据存储 |
| 缓存 | Redis | 热数据缓存、分布式锁、计数器、队列辅助 |
| 消息队列 | RabbitMQ、Kafka、RocketMQ | 异步解耦、削峰填谷、事件流处理 |
| 注册配置 | Nacos、Consul、etcd | 服务发现、配置管理、健康检查 |
| 日志搜索 | Elasticsearch、Logstash、Filebeat、Kibana | 日志采集、检索、分析 |
| 对象存储 | MinIO、S3 | 文件、备份、静态资源存储 |
| 监控告警 | Prometheus、Grafana、Alertmanager | 指标采集、展示、告警 |

运维学习中间件时，重点不是“会安装”，而是要能围绕生产维护回答：

- 它解决什么问题。
- 它部署在哪里。
- 它依赖哪些端口、目录、配置和权限。
- 它的数据如何持久化。
- 它如何备份和恢复。
- 它如何扩容和高可用。
- 它有哪些核心监控指标。
- 它出现故障时如何排查。

## 二、通用学习模板

每学习一个中间件，都建议按下面这套模板整理笔记。

### 1. 基础认知

- 这个组件解决什么问题。
- 它处在业务架构的哪一层。
- 它的核心概念有哪些。
- 它和同类组件有什么区别。

### 2. 部署信息

- 安装方式：包管理器、二进制、Docker、Helm。
- 配置文件路径。
- 数据目录路径。
- 日志目录路径。
- 默认端口。
- 启动、停止、重启方式。

### 3. 常用配置

- 监听地址和端口。
- 数据持久化配置。
- 用户和权限配置。
- 资源限制配置。
- 日志级别和日志格式。
- 安全相关配置。

### 4. 运维动作

- 启停服务。
- 查看状态。
- 查看日志。
- 备份数据。
- 恢复数据。
- 扩容节点。
- 滚动变更。
- 清理历史数据。

### 5. 高可用与容灾

- 单机模式适合什么场景。
- 主从、哨兵、集群、分片分别解决什么问题。
- 故障切换如何触发。
- 备份是否做过恢复验证。
- 是否存在单点风险。

### 6. 监控指标

- 服务是否存活。
- 连接数。
- 请求量或 QPS。
- 延迟。
- 错误率。
- CPU、内存、磁盘、网络。
- 组件特有指标，例如 Redis 内存命中率、MySQL 慢查询、Kafka 消费积压。

### 7. 故障排查

排查时建议按这个顺序：

```text
现象 -> 影响范围 -> 最近变更 -> 服务状态 -> 日志 -> 配置 -> 网络 -> 资源 -> 数据 -> 恢复动作
```

## 三、Web 与代理：Nginx

配套笔记：[nginx-notes.md](./nginx-notes.md)

### 核心用途

- 托管静态站点。
- 反向代理后端服务。
- 做七层负载均衡。
- 统一 HTTPS 入口。
- 按域名或路径分发流量。
- 记录访问日志和错误日志。

### 必会知识点

- `server` 与 `location` 匹配。
- `proxy_pass` 反向代理。
- `upstream` 负载均衡。
- `access_log` 和 `error_log`。
- HTTPS 证书配置。
- 配置检查与热重载。

### 常用命令

```bash
nginx -t
nginx -s reload
systemctl status nginx
systemctl restart nginx
tail -f /var/log/nginx/access.log
tail -f /var/log/nginx/error.log
```

### 常见故障

| 现象 | 常见原因 |
|---|---|
| 403 | 目录权限不足、缺少首页文件、配置禁止访问 |
| 404 | 路径不匹配、root/alias 配置错误 |
| 502 | 后端服务不可用、端口错误、连接被拒绝 |
| 504 | 后端响应超时、网关超时配置过短 |
| HTTPS 失败 | 证书路径错误、证书过期、server_name 不匹配 |

## 四、数据库：MySQL / PostgreSQL

### 核心用途

- 存储结构化业务数据。
- 支持事务、索引、查询和权限控制。
- 通过备份、复制和高可用机制保障数据安全。

### 必会知识点

- 用户和权限。
- 数据库、表、索引基础。
- 连接数和慢查询。
- 备份与恢复。
- 主从复制。
- 事务和锁的基本排查。

### MySQL 常用命令

```bash
mysql -uroot -p
mysqldump -uroot -p database_name > backup.sql
mysql -uroot -p database_name < backup.sql
systemctl status mysql
tail -f /var/log/mysql/error.log
```

### 重点监控指标

- 是否存活。
- 当前连接数。
- 最大连接数。
- QPS/TPS。
- 慢查询数量。
- 主从延迟。
- 磁盘空间。
- 锁等待。

### 常见故障

| 现象 | 常见原因 |
|---|---|
| 无法连接 | 服务未启动、端口未监听、防火墙、安全组、账号权限 |
| 连接数满 | 应用连接未释放、连接池配置过大、max_connections 过小 |
| 查询慢 | 缺少索引、SQL 写法问题、数据量大、锁等待 |
| 主从延迟 | 从库性能不足、大事务、网络延迟 |
| 磁盘满 | binlog、慢日志、数据文件增长过快 |

## 五、缓存：Redis

### 核心用途

- 缓存热点数据。
- 计数器、排行榜、限流。
- 分布式锁。
- 简单队列。
- 会话缓存。

### 必会知识点

- 常见数据类型：String、Hash、List、Set、ZSet。
- 持久化：RDB、AOF。
- 主从复制。
- 哨兵模式。
- Cluster 集群。
- 内存淘汰策略。

### 常用命令

```bash
redis-cli ping
redis-cli info
redis-cli info memory
redis-cli info replication
redis-cli slowlog get 10
redis-cli client list
```

### 重点监控指标

- 内存使用量。
- 命中率。
- 连接数。
- QPS。
- 慢命令。
- key 数量。
- 主从复制状态。
- 持久化状态。

### 常见故障

| 现象 | 常见原因 |
|---|---|
| 内存过高 | key 无过期时间、大 key、缓存雪崩 |
| 访问慢 | 慢命令、大 key、网络抖动、CPU 打满 |
| 数据丢失 | 持久化配置不合理、误删、主从切换异常 |
| 连接数满 | 应用连接泄漏、连接池配置不合理 |
| 主从异常 | 网络故障、认证配置不一致、复制积压 |

## 六、消息队列：RabbitMQ / Kafka

### 核心用途

- 异步处理。
- 系统解耦。
- 削峰填谷。
- 事件驱动。
- 日志流和数据流处理。

### RabbitMQ 重点

- Exchange。
- Queue。
- Binding。
- Routing Key。
- ACK。
- Dead Letter Queue。
- 消息堆积。

### Kafka 重点

- Topic。
- Partition。
- Broker。
- Producer。
- Consumer Group。
- Offset。
- 消费积压。

### 重点监控指标

- 消息生产速率。
- 消息消费速率。
- 消息堆积量。
- 消费延迟。
- Broker 状态。
- 磁盘空间。
- 副本同步状态。

### 常见故障

| 现象 | 常见原因 |
|---|---|
| 消息积压 | 消费者处理慢、消费者数量不足、下游服务异常 |
| 消息丢失 | ACK 配置不当、持久化配置不足、生产者未确认 |
| 重复消费 | 消费确认失败、消费者重启、业务未做幂等 |
| Broker 异常 | 磁盘满、内存不足、网络中断 |

## 七、注册配置：Nacos / Consul / etcd

### 核心用途

- 服务注册。
- 服务发现。
- 配置集中管理。
- 健康检查。
- 分布式协调。

### 必会知识点

- 服务实例。
- 命名空间。
- 配置分组。
- 健康检查。
- 配置变更。
- 集群一致性。

### 运维关注点

- 配置变更是否可追踪。
- 是否有权限控制。
- 是否有配置备份。
- 服务实例是否异常下线。
- 集群节点是否健康。

---

## 八、日志搜索：ELK / EFK

### 核心用途

- 采集系统日志和应用日志。
- 建立统一日志检索入口。
- 快速定位故障。
- 支持告警和趋势分析。

### 常见组合

| 组合 | 组件 |
|---|---|
| ELK | Elasticsearch + Logstash + Kibana |
| EFK | Elasticsearch + Fluent Bit / Fluentd + Kibana |
| Beats | Filebeat / Metricbeat / Packetbeat |

### 必会知识点

- 索引。
- 分片。
- 副本。
- Mapping。
- 日志采集路径。
- 日志字段规范。
- 索引生命周期管理。

### 常见故障

| 现象 | 常见原因 |
|---|---|
| 查不到日志 | 采集器未运行、路径错误、索引名错误、时间范围错误 |
| ES 集群黄/红 | 副本不可分配、节点故障、磁盘水位过高 |
| 写入慢 | 分片过多、磁盘慢、批量写入配置不合理 |
| 磁盘增长快 | 日志量过大、未配置生命周期、保留时间过长 |

## 九、对象存储：MinIO

### 核心用途

- 保存图片、视频、附件。
- 保存备份文件。
- 作为 S3 兼容对象存储实验环境。
- 给应用提供文件上传下载能力。

### 必会知识点

- Bucket。
- Object。
- Access Key / Secret Key。
- Policy。
- Endpoint。
- 生命周期。

### 运维关注点

- 数据目录是否持久化。
- 访问密钥是否安全。
- Bucket 权限是否过大。
- 是否有备份策略。
- 磁盘空间是否充足。

## 十、监控与告警：Prometheus / Grafana

### 核心用途

- 采集中间件指标。
- 展示趋势图。
- 设置告警。
- 辅助容量规划和故障定位。

### 常见 Exporter

| 组件 | Exporter |
|---|---|
| 主机 | node_exporter |
| MySQL | mysqld_exporter |
| Redis | redis_exporter |
| Nginx | nginx-prometheus-exporter |
| Kafka | kafka_exporter |
| Elasticsearch | elasticsearch_exporter |

### 告警设计建议

- 告警要区分严重程度。
- 告警条件要设置持续时间，避免瞬时抖动。
- 告警信息要包含实例、组件、指标、当前值。
- 告警需要有处理手册。
- 重要告警要做恢复通知。

## 十一、中间件实践清单

### 实践一：基础 Web 架构

```text
User -> Nginx -> App -> MySQL
                     -> Redis
```

目标：

- 理解入口层、应用层、数据库、缓存的关系。
- 练习 Nginx 反向代理。
- 练习 MySQL 和 Redis 基础部署。
- 练习日志排查。

### 实践二：高可用实验

目标：

- MySQL 主从复制。
- Redis 主从与哨兵。
- Nginx 多后端负载均衡。
- 模拟节点故障并观察恢复过程。

### 实践三：消息队列实验

目标：

- 发送和消费消息。
- 模拟消息积压。
- 观察消费者异常时的表现。
- 理解 ACK、重试和死信。

### 实践四：日志平台实验

目标：

- 采集 Nginx 或应用日志。
- 写入 Elasticsearch。
- 使用 Kibana 查询日志。
- 模拟一次 404/502 并通过日志定位。

### 实践五：监控平台实验

目标：

- 使用 Prometheus 采集主机和中间件指标。
- 使用 Grafana 展示仪表盘。
- 配置基础告警。
- 为 MySQL、Redis、Nginx 各设计 3 个核心指标。

## 十三、总结

中间件学习要围绕真实运维动作展开：

```text
部署 -> 配置 -> 验证 -> 日志 -> 备份 -> 监控 -> 高可用 -> 故障排查
```

只会安装还不够。能解释架构、能看懂日志、能恢复数据、能设计监控、能处理故障，才算真正具备中间件运维能力。
