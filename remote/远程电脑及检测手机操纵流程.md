# 远程电脑及检测设备运维流程

> 本文是通用 Runbook。FRP 部署细节和配置示例见 [FRP 内网穿透部署与排障](FRP.md)。

本文是一份通用 Runbook，用于检查和恢复远程电脑、FRP 通道、远程控制工具以及连接在电脑上的检测设备。真实资产、账号、密码、token、设备 ID 和内部下载地址应从 CMDB 与密码管理器获取。

## 1. 操作前准备

- 确认变更窗口、影响范围和现场联系人。
- 从 CMDB 获取目标资产、FRP 映射、远程控制设备和设备数量。
- 从密码管理器临时获取凭据，不在聊天、截图或笔记中传播。
- 准备备用接入方式，例如堡垒机、受控远程桌面或现场协助。
- 记录当前状态，避免恢复过程中丢失原始故障信息。

## 2. 远程电脑连接检查

### 2.1 首选接入路径

优先通过堡垒机或企业远程接入平台连接。需要使用 Windows 远程桌面时：

```powershell
Test-NetConnection <frp-server> -Port <rdp-mapped-port>
mstsc /v:<frp-server>:<rdp-mapped-port>
```

不要把账号密码写进命令、脚本或共享文档。

### 2.2 FRP 不可用时

通过备用远程控制工具进入目标电脑，然后检查：

1. 电脑是否在线、休眠或处于锁死状态。
2. VPN 是否连接到指定节点。
3. `frpc` 进程是否存在。
4. `frpc` 日志是否显示代理启动成功。
5. 本地目标服务是否监听，例如 RDP 的 `3389` 端口。

```powershell
Get-Process frpc -ErrorAction SilentlyContinue
Get-NetTCPConnection -LocalPort 3389 -State Listen
Test-NetConnection <frp-server> -Port <frps-port>
```

如果 `frpc` 未运行，使用受控脚本或任务计划重新启动。确认新进程正常后再关闭旧窗口，避免同时运行多个客户端实例。

## 3. 检测设备检查

### 3.1 正常状态标准

- CMDB 中登记的设备数量与当前在线数量一致。
- ADB 能识别所有授权设备。
- 每台设备的隧道进程处于运行状态。
- SSH 映射端口可达。
- SOCKS5 测试返回预期的出口 IP 和地区。

```bash
adb devices -l
```

从授权测试机验证单台设备：

```bash
ssh -p <ssh-port> <device-user>@<frp-server>
curl --fail --show-error --proxy "socks5h://<user>:<password>@<frp-server>:<socks-port>" https://api.ipify.org
```

避免把带密码的完整代理 URL 写入 Shell 历史。实际操作可临时读取环境变量，完成后立即清除。

### 3.2 设备离线恢复

1. 保存当前日志和故障截图到受控工单。
2. 关闭失效的 ADB、scrcpy 和隧道进程。
3. 执行 `adb kill-server`，再执行 `adb start-server`。
4. 重新连接设备，并在设备端确认 USB 调试授权。
5. 按“设备端隧道 -> 电脑端转发”的顺序启动脚本。
6. 逐台验证 SSH 和 SOCKS5，不只检查窗口是否出现。

```bash
adb kill-server
adb start-server
adb devices -l
```

如果设备状态是 `unauthorized`，需要现场人员在设备上确认授权；如果是 `offline`，检查 USB 线、供电、驱动和 ADB 版本。

## 4. Windows 主机排查

### 4.1 检查异常关机与重启

打开事件查看器：

```text
Win + R -> eventvwr.msc -> Windows 日志 -> 系统 -> 筛选当前日志
```

常用事件 ID：

| 事件 ID | 含义 |
|---|---|
| 1074 | 用户或程序发起关机、重启 |
| 6006 | 事件日志服务正常停止，通常表示正常关机 |
| 6005 | 事件日志服务启动，通常表示系统启动 |
| 41 | 未正常关机后重新启动，常见于断电或崩溃 |
| 6008 | 上一次关机异常 |

### 4.2 检查电源策略

```powershell
powercfg /getactivescheme
powercfg /requests
powercfg /lastwake
```

远程节点应根据组织策略禁用不必要的自动睡眠，但不要在不了解现场要求时直接修改电源计划。

### 4.3 检查网络链路

```powershell
ipconfig /all
Get-NetRoute | Sort-Object RouteMetric | Select-Object -First 20
Test-NetConnection <default-gateway>
Test-NetConnection <frp-server> -Port <frps-port>
tracert <frp-server>
```

按“本机网卡 -> 默认网关 -> VPN -> FRP 服务端 -> 映射端口 -> 本地业务服务”的顺序定位，避免跳步。

## 5. 故障分层

| 现象 | 优先检查 |
|---|---|
| 备用远程工具也离线 | 主机电源、现场网络、代理设备状态 |
| 备用远程工具在线但 FRP 离线 | VPN、`frpc` 进程、token、服务端端口 |
| FRP 端口可达但 RDP 失败 | RDP 服务、Windows 防火墙、本地 `3389` 监听 |
| ADB 看不到设备 | USB、驱动、调试授权、ADB 服务 |
| SSH 可用但 SOCKS5 不可用 | 设备端代理进程、端口映射、认证配置 |
| 所有设备同时异常 | 电脑网络、VPN、FRP 或公共脚本版本 |

## 6. 批量变更要求

批量升级脚本、客户端或配置时：

1. 先备份原文件和当前配置。
2. 校验下载地址、文件哈希和发布来源。
3. 先在一台非关键节点验证。
4. 验证启动、重启、断网恢复和开机自启。
5. 再按小批次推广，每批保留观察时间。
6. 出现异常立即停止并回滚，不继续扩大影响范围。

不要执行来源不明的远程脚本，也不要使用 `curl ... | bash` 直接运行未审查内容。

## 7. 完成标准

- 远程电脑可通过首选接入路径连接。
- FRP 客户端和服务端日志无持续错误。
- 设备在线数量与资产记录一致。
- 每台设备的 SSH、SOCKS5 和出口 IP 验证通过。
- 自动启动机制经过一次重启验证。
- 工单记录故障原因、操作、验证结果、遗留风险和后续动作。
